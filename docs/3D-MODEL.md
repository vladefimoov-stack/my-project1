# 3D model & product imagery

## What exists today

| Asset | Status |
|---|---|
| `components/product-viewer/PhoneModel.tsx` | **Provisional procedural 3D model** — real geometry built in code with Three.js (not a flat image). Separate meshes and materials for body, front glass, display, earpiece, every keypad key (17), the D-pad ring and centre button, rear camera module (2 lenses + flash), back wordmark, speaker holes, USB-C port, microphones and side keys. |
| `public/models/keyline-one-provisional.glb` | The same model exported to binary glTF (open it in Blender, three.js editor, etc.). |
| `public/images/renders/*.webp` | Studio renders **of the provisional model**, generated by `npm run renders`. They are honest computer renders, not photographs of the physical device. |
| `lib/device.ts` | All physical dimensions (mm) and keypad layout used by the 3D model *and* the CSS virtual phone, so every depiction stays consistent. |

The model was reconstructed from the two reference photographs (supplier listing + hand-held video frame). It reproduces: a narrow rounded graphite body, a 3:4 colour touchscreen under a black glass panel in the upper half, a soft-key row (alarm / back icons), call & end keys, a large circular D-pad with centre button spanning the two upper key rows, a 4×3 numeric grid with thin dark separations, and a vertical dual-lens camera module in the upper left of the back.

## Details that still require verification against a physical sample

Everything in `lib/device.ts` is an estimate. In particular:

- [ ] Exact outer dimensions (currently 55 × 132 × 11.5 mm) and corner radius.
- [ ] Screen size and aspect ratio (currently a 46 × 61.3 mm, 3:4 active area).
- [ ] Glass panel shape / chin height below the screen.
- [ ] Key sizes, gap widths, legend fonts and the exact icons on the soft keys.
- [ ] D-pad diameter and whether it is a ring + centre key or a single rocker.
- [ ] Rear camera module size and position, number of lenses, flash position.
- [ ] **Side buttons, ports and microphones are assumed** (volume rocker + key on the right side, USB-C at the bottom, top microphone). Not visible in the references.
- [ ] Back cover texture/finish and any printed markings.
- [ ] Available colours.

## Replacing it with a production model (no rebuild of the website)

1. Get a proper model (CAD from the manufacturer, a photogrammetry scan of a sample, or a Blender model built from accurate measurements). Use real-world metres or millimetres, Y-up, front facing +Z, origin at the centre of the body.
2. Optimise: `npx @gltf-transform/cli optimize phone.glb phone-opt.glb --compress draco --texture-compress webp` (target < 3 MB).
3. Copy to `public/models/phone.glb`.
4. In `config/product.ts` set `model.glbUrl: "/models/phone.glb"` and adjust `glbScale` so the phone is ~1.32 units tall (e.g. `0.01` for a model in millimetres, `10` for metres).
5. Run `npm run dev` and `npm run renders` to regenerate all product images from the new model.

If the model is a GLB with its own screen material, the virtual launcher texture is not applied — that's expected.

## Regenerating renders

```bash
npm run dev            # in one terminal
npm run renders        # in another — needs Playwright + Chromium
npm run renders hero front   # only some views
```

Outputs `public/images/renders/*.webp`, `public/images/og.jpg`, `public/models/keyline-one-provisional.glb`
and `lib/render-manifest.json` (image sizes used by `next/image`).

The prompt asks for photorealistic product photography, including the device in someone's hand. No image-generation model was available in the build environment, and generated "photos" of a product that doesn't exactly match the real one would be misleading. Recommended before launch:

- [ ] Studio photos of a real sample on white (front, back, ¾, side, keypad macro, screen macro).
- [ ] Lifestyle photo of the device in a hand (replaces the bank-card scale comparison or sits next to it).
- [ ] Short video of the touchscreen + keypad in use (optional).

Drop them into `public/images/` and swap the `src` values in `components/hero/Hero.tsx`, `components/sections/Presentation.tsx` and `components/sections/Purchase.tsx`.
